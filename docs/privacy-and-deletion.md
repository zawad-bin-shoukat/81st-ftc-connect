# Privacy and account deletion

The backend serves a public privacy policy at `/privacy` and a public account-deletion page at `/account-deletion`. Use the deployed HTTPS URLs for the App Store privacy-policy field, Google Play privacy-policy field, and Google Play account-deletion URL. The public operator/contact is Sakib Ahmed Shanto, `sakibahmedshanto15@gmail.com`. Review this policy with the client before store submission and whenever hosting, SMS delivery, photo storage, or retention practices change.

Signed-in members can choose **My profile → Delete my account** and type `DELETE`. `DELETE /me` requires a valid session and `{ "confirm": "DELETE" }`. It deletes the member's app profile, sign-in account and all sessions, invitations, and associated OTP challenges in one database transaction. A registration submission with the same FTC ID and verified login number is removed; unrelated registration reviews retain their outcome but no longer identify them as reviewer. Staff/test accounts can delete their separate profile in the same way. This feature does not delete or edit the original roster document held outside the app. No current participant records are altered by deploying this feature; deletion happens only when the account owner invokes it.

The web page offers the same deletion after phone OTP verification, plus a public support email for people unable to sign in. Support must verify ownership before manually handling a request. Do not ask users to email OTP codes. The web page keeps its session token in browser memory only.

The scheduled Mac backups are retained for roughly 30 days. Deleting an account removes it from the live app database immediately, but older backup copies can still contain it until rotation. **Do not restore a backup over the live database without reapplying every deletion and profile change made after that backup.** Likewise, any future roster import must exclude members who deleted their app profile, or it would recreate them. Account deletion now removes stored R2 photo objects before removing the profile. The original organizer photo source and any separate photo backups require their own retention/deletion process.

## Scheduled retention cleanup

`apps/backend/prisma/retention.sql` removes expired OTP challenges, rate-limit windows, and expired/revoked sessions on the next run; invitations 30 days after expiry, consumption, or revocation; and pending or reviewed membership requests after 90 days. It never deletes `members`, `accounts`, or `test_accounts`. The SQL is transactional and has short lock and statement timeouts. Run `./scripts/backend.sh retention:check` first: it creates a uniquely named local test database, applies all migrations, seeds only synthetic data, checks every cleanup category, and drops that test database. It refuses nonlocal `DATABASE_URL` values.

`.github/workflows/retention.yml` schedules cleanup for 03:37 UTC (09:37 Bangladesh) daily and also allows a manual run. Before pushing it, add the GitHub Actions repository secret `NEON_RETENTION_DATABASE_URL` with the **direct**, TLS-enabled Neon connection URL (not the pooled URL). Never put that URL in Git or a chat. After pushing, run the workflow manually once in GitHub Actions and verify a green result. If it fails, inspect the workflow log and fix the cause before relying on the public policy's retention description. Review workflow history regularly: GitHub can delay or drop scheduled jobs and disables scheduled workflows in public repositories after 60 days without repository activity. The manual run remains available for recovery.

This GitHub schedule is a pilot arrangement. Before store release, move the job to a scheduler that does not pause when the repository is inactive (for example, a Neon scheduled Function Trigger), and use a database credential limited to these maintenance operations instead of the database owner URL.

The integration check in `apps/backend/scripts/check-auth.mjs` exercises both member and test-account deletion using a disposable database. It must be run locally with PostgreSQL available. Never run mutation tests against Neon or the imported roster.
